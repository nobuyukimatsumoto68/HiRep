# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

HiRep is a lattice QCD simulation code written in C99, supporting SU(N)/SO(N) gauge theories with fermions in various representations (fundamental, adjoint, symmetric, antisymmetric). It targets CPU (serial/OpenMP/MPI) and GPU (CUDA/HIP) execution.

## Build System

The build system uses [ninja](https://ninja-build.org/) via a Perl wrapper. The `Make/nj` script must be in your `PATH`.

```bash
# Compile everything from the root
nj

# Compile only one application (e.g., pure gauge simulation)
cd PureGauge && nj

# Compile only the library
nj libhr.a
```

`nj` auto-regenerates `build/build.ninja` via `Make/build.pl` on every invocation. All intermediate build artifacts go into `build/` at the root.

### Configuration

All compile-time parameters live in `Make/MkFlags.ini`. Generate or update it with:

```bash
Make/write_mkflags.pl [options]   # writes Make/MkFlags.ini
Make/write_mkflags.pl -h          # full option list
```

Key options:
- `-n <int>` — number of gauge colors (NG, default 2)
- `-r FUND|ADJ|SYMM|ASYM` — fermion representation
- `--gauge SUN|SON` — gauge group
- `-mpi` / `-no-mpi` — MPI support
- `--gpu` / `--no-gpu` — CUDA/HIP GPU support (also requires `--newgeo`)
- `--omp` / `--no-omp` — OpenMP
- `-t P|A|T|O`, `-x P|A|T|O`, etc. — boundary conditions per direction (P=periodic, A=antiperiodic, T=theta, O=open)
- `--clover` / `--expclover` — clover fermion action variants
- `--cc`, `--mpicc`, `--nvcc`, `--cflags`, `--gpuflags`, `--ldflags` — compiler overrides

## Running Tests

The test system uses ninja targets of the form `TestProgram/<Module>_tests` which both build and run the tests in that module.

```bash
# Build and run a single test module (e.g., Geometry):
nj TestProgram/Geometry_tests

# Automated test runner: writes MkFlags, builds, and runs a list of modules:
TestProgram/run_tests.sh "Algebra Geometry Inverters Sources Utils" -n 2 -r FUND -mpi

# Run with specific options (e.g., no MPI, 3 colors, OMP):
TestProgram/run_tests.sh "Algebra DiracOperator" -n 3 -r FUND -no-mpi -omp
```

Individual test binaries live in `TestProgram/<Module>/` alongside a default `input_file`. All tests must run without arguments and return `0` on success. MPI tests are dispatched via `Make/Utils/test_wrapper.pl`, which reads `input_file` for the process count.

## Code Format

Formatting uses clang-format (config in `.clang-format`, column limit 128, indent 4 spaces). The pre-commit hook and CI enforce it:

```bash
# Check formatting on staged changes (same as CI)
Make/git-hooks-pre-commit

# Check all files
Make/git-hooks-pre-commit -a
```

CI requires clang-format version 17.

## Architecture

### Directory Layout

- `Include/` — public headers, one per module; `Include/Core/` has foundational types
- `LibHR/` — library implementation, mirroring `Include/` module structure
- `HMC/`, `PureGauge/`, `Spectrum/`, `WilsonFlow/`, etc. — application executables, each with a `main.c` and `input_file`
- `TestProgram/` — unit/integration tests, organized into module subdirectories matching `LibHR/`
- `Make/` — build scripts, `MkFlags.ini`, environment files for HPC clusters (LUMI, Hippo)
- `build/` — all compiled objects and `build.ninja` (gitignored)

### Key Design Patterns

**Compile-time parametrization**: gauge group, fermion representation, and number of colors are resolved at compile time. The headers `suN.h`, `suN_types.h`, and `spinor_field.h` are auto-generated by `Make/Utils/write_suN_headers.pl` and `Make/Utils/autosun/writeREPR` from templates in `Include/Core/TMPL/`. Never edit generated headers directly.

**Field structs**: All lattice fields (spinor fields, gauge fields) are declared with the `_DECLARE_FIELD_STRUCT` macro in `Include/Core/spinor_field.h`. The struct conditionally includes GPU (`gpu_ptr`) and MPI (`comm_req`, send/recv buffers) members depending on compile flags.

**Global variables**: `GLB_VAR(type, name, init)` in `Include/Core/global.h` declares lattice dimensions (`GLB_T/X/Y/Z`), process grid (`NP_T/X/Y/Z`), and other globals. Exactly one translation unit defines `GLOBAL_DEF` before including headers to instantiate storage.

**Site-loop macros**: `_SITE_FOR`, `_PIECE_FOR`, `_MASTER_FOR`, etc. abstract CPU/GPU iteration over lattice sites. These are registered in `.clang-format`'s `ForEachMacros` so they format correctly.

**TMPL pattern**: Subdirectories named `TMPL/` contain `.c.tmpl` / `.h.tmpl` files that are instantiated for multiple types (e.g., single/double precision, CPU/GPU). The build system handles instantiation.

### Library Modules (`LibHR/` and `Include/`)

| Module | Contents |
|---|---|
| `Core` | Global state, spinor field allocation primitives, GPU complex type |
| `Geometry` | Lattice geometry, MPI decomposition, halo communications |
| `Inverters` | CG, BiCGstab, MINRES, multi-shift solvers, eigenvalue solver (EVA) |
| `Update` | HMC integrators, Dirac operator (`Dphi`), clover tools, force terms |
| `Observables` | Plaquette, Polyakov loop, mesonic correlators, Wilson loops |
| `IO` | Gauge configuration read/write |
| `Memory` | Field memory allocation/deallocation |
| `Utils` | SU(N) algebra utilities, smearing, group exponential |
| `Random` | Random number generator (RANLUX) |

### Application Executables

Each application directory has a main `.c` file and an `input_file`. Programs are run as:
```bash
./hmc -i input_file                          # serial
mpirun -np <N> ./hmc -i input_file           # MPI
```
Output goes to `out_0` by default (only rank 0 writes); use `-o <name>` to change.

The `last conf = +N` syntax in input files means "N additional trajectories from current", while `last conf = N` means "stop at trajectory N".

## CI

GitHub Actions runs a matrix over `nc ∈ {2,3}`, `repr ∈ {FUND,ADJ}`, `mpi`, `omp`, and `expclover`. Workflows are in `.github/workflows/`. The test Docker image is `cpica/hr-tests`.
